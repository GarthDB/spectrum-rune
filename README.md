# spectrum-rune

Adobe Spectrum components for [Rune](https://github.com/anomalyco/rune), a Rust UI toolkit.
Every colour, size, radius and type value comes from the Spectrum design data, generated by the
`design-data` CLI into plain Rust (`cargo xtask gen`); the components only arrange those values.

Status: pre-release, not published. Rune itself is pre-release, so the `rune` dependency is pinned
by git rev (see [Installing](#installing)) and may change.

Built so far (all verified against Spectrum's own renderer, see [Verification](#how-verification-works)):

| Component | Module | State the app owns |
|---|---|---|
| Switch | `switch` | `selected` |
| Checkbox (incl. indeterminate, error) | `checkbox` | `selected` |
| Radio button (one button, not a group) | `radio_button` | `selected` |
| Button | `button` | none (`pending` and `disabled` are inputs) |
| Action button | `action_button` | `selected` for a toggle |
| Badge | `badge` | none (static) |
| Radio group | `radio_group` | `value` |
| Accordion item (one item) | `accordion` | `open` |
| Accordion (a group of items; single or multiple) | `accordion_group` | the open set |

## Installing

The crate is not on crates.io. Depend on it by path or git, and pin Rune to the same rev this
repo uses (the workspace `Cargo.toml` is the source of truth):

```toml
[dependencies]
spectrum-rune = { path = "../spectrum-rune/crates/spectrum-rune" }
rune = { git = "https://github.com/anomalyco/rune", rev = "16697feebc536c8cd09c28d62105ea5d46cb024a" }
rune-kit = { git = "https://github.com/anomalyco/rune", rev = "16697feebc536c8cd09c28d62105ea5d46cb024a" }
```

`rune-kit` is needed because Button and Action button borrow its progress indicator.
The toolchain is pinned in `rust-toolchain.toml`.

## Using it

Tokens are chosen per colour scheme and scale; hand the `&'static Tokens` to every `build`:

```rust,no_run
use rune::{col, AppSpec, Cx, El};
use spectrum_rune::switch::Switch;
use spectrum_rune::tokens::{tokens, ColorScheme, Scale};

struct App {
    wifi: bool,
}

fn view(app: &App, cx: &mut Cx<App>) -> El {
    let scheme = if cx.system_dark() { ColorScheme::Dark } else { ColorScheme::Light };
    let t = tokens(scheme, Scale::Desktop); // Scale::Mobile for the touch sizes
    col().padding(16.0).child(
        Switch::new("wifi")
            .label("Wi-Fi")
            .selected(app.wifi)
            .on_toggle(|app: &mut App| app.wifi = !app.wifi)
            .build(t),
    )
}

fn main() {
    rune::run(AppSpec::new("demo", (320.0, 120.0), || App { wifi: false }, view));
}
```

**State.** A component is a builder that returns an `El` for one frame. It never stores
`selected` or `open`: you pass the current value in and flip your own state in the handler
(`on_toggle`, `on_select`, `on_press`), as above. Rune rebuilds the view after the handler runs.

**Keys and `Interaction`.** Hover and press colours are whole-colour swaps, so a component rebuilds
with the pointer state it reads from `interaction::Interaction::of(key)`. The `key` you pass to
`Component::new(key)` is that lookup, so it must be unique per instance across the whole view
(two buttons with the same key share a hover). It also prefixes the parts, `{key}/container`,
`{key}/label` and so on, which is what `rt.find(..)` and scripts address. Keyboard focus needs no
state: Rune draws the focus ring, `focus_fill` and `hover_group_focus` colours only for the keyboard.

**Sizes.** Switch, Checkbox, Radio button, Button, Badge and Accordion item take `Size` (`S`, `M`,
`L`, `XL`). Action button's recipe also has `XS`, so it takes `ActionButtonSize`; a plain `Size`
converts, so `.size(Size::M)` works there too, while `XS` on a Switch does not compile.

**Width and wrapping.** Switch, Checkbox, Radio button, Button and Badge hug their content, and a label
never wraps, unless you give a request width: `.width(150.0)` (the oracle's `--width`) makes the
root that wide (a Button never narrower than 2.25 x its height) and wraps a label that does not fit,
growing the root by one line height per extra line, with the control or icon centred on the first
line. Action button and Accordion item have no such recipe.

**Option constraints.** Spectrum's catalogs say which option combinations are undefined (an accent
button has no outline, for instance). Builders `debug_assert!` that, so a bad combination panics in
debug builds and renders what the reference renders in release. Call `constraints::check(name,
&component.options())` to test a combination yourself; the gallery does, and skips the invalid ones.

One minimal use of each (all compiled by `cargo test`, as doctests of this file):

```rust,no_run
use rune::El;
use spectrum_rune::accordion::{AccordionItem, Density};
use spectrum_rune::action_button::ActionButton;
use spectrum_rune::badge::{self, Badge};
use spectrum_rune::button::{self, Button};
use spectrum_rune::checkbox::Checkbox;
use spectrum_rune::icons::ADD_100;
use spectrum_rune::radio_button::RadioButton;
use spectrum_rune::tokens::Tokens;
use spectrum_rune::Size;

struct App {
    agree: bool,
    pick: u8,
    bold: bool,
    open: bool,
}

fn parts(app: &App, t: &'static Tokens) -> Vec<El> {
    vec![
        Checkbox::new("agree")
            .label("I agree")
            .selected(app.agree)
            .on_toggle(|a: &mut App| a.agree = !a.agree)
            .build(t),
        RadioButton::new("pick-1")
            .label("One")
            .selected(app.pick == 1)
            .on_select(|a: &mut App| a.pick = 1)
            .build(t),
        Button::new("save")
            .label("Save")
            .variant(button::Variant::Primary)
            .style(button::Style::Outline)
            .icon(&ADD_100)
            .size(Size::L)
            .on_press(|_: &mut App| println!("saved"))
            .build(t),
        ActionButton::new("bold")
            .label("Bold")
            .quiet(true)
            .selected(app.bold)
            .on_press(|a: &mut App| a.bold = !a.bold)
            .build(t),
        Badge::new("status")
            .label("Approved")
            .variant(badge::Variant::Positive)
            .style(badge::Style::Subtle)
            .build(t),
        AccordionItem::new("details")
            .title("Details")
            .density(Density::Regular)
            .open(app.open)
            .on_toggle(|a: &mut App| a.open = !a.open)
            .content(rune::text("Content below the header."))
            .build(t),
    ]
}
```

## Gallery

`crates/spectrum-rune/examples/gallery` shows every component with its interesting options. The
toggles really toggle (click or Space/Enter), and the header switches the colour scheme and the
scale live. Its page colour is Spectrum's `background_base_color` (white in light, near-black in dark; the oracle's scenes have no backdrop, so this is the named page token).

```sh
cargo run -p spectrum-rune --example gallery
cargo run -p spectrum-rune --example gallery -- --list-scenes
```

Headless screenshots (need a GPU; Rune renders offscreen). A scene is a component, optionally
suffixed `-dark` (forces the dark scheme) or `-mobile` (the mobile scale). Without `--theme`, a
snapshot follows the machine's current appearance:

```sh
cargo run -p spectrum-rune --example gallery -- --scene button --theme dark --size 1100x1000 --snap /tmp/button-dark.png
cargo run -p spectrum-rune --example gallery -- --scene button-mobile --theme light --snap /tmp/button-mobile.png
```

Scenes: `switch`, `checkbox`, `radio-button`, `button`, `action-button`, `badge`, `accordion`, `accordion-group`.

CI also renders every scene with Rune's CPU reference renderer (no GPU) and uploads the PNGs as the
`gallery` artifact; locally: `cargo test --release -p spectrum-rune --example gallery -- --ignored`
writes them to `target/gallery/`.

## Fonts

Spectrum's typeface, Adobe Clean Spectrum VF, is licensed. **It is never committed or embedded
here.** Rune loads installed fonts by family name, and the components ask for this list
(`font::FAMILY_LIST`):

```text
Adobe Clean Spectrum VF, Adobe Clean Spectrum, Source Sans 3
```

Without the licensed font you get the next name that is installed, ending at Rune's default sans.
Source Sans 3 is only a width-compatible stand-in (it is what the `design-data` CLI measures text
with); nothing will look like Spectrum, and text widths can differ slightly. To see the real thing,
install the font files you are licensed for into the system (macOS: open them in Font Book; Linux:
copy to `~/.local/share/fonts` and run `fc-cache -f`). The gallery measures a sample string against
Rune's default sans to tell whether the family resolved, and says so in its header and on startup
(`Adobe Clean Spectrum VF found` or `... NOT found: showing the fallback`). The same check runs as
the ignored tests in `src/font.rs`: `cargo test -p spectrum-rune -- --ignored`.

### Text smoothing

On macOS, Rune defaults to `FontSmoothing::On` (CoreText with font smoothing's outline dilation),
which draws heavier and less crisp than Spectrum on the web. `FontSmoothing::Off` is what
`-webkit-font-smoothing: antialiased` draws in macOS browsers, and is the closer match. Smoothing is
a window setting in Rune, so components can't set it: **the app does**.

```rust
use rune::{App, FontSmoothing};

App::new(spec).font_smoothing(FontSmoothing::Off).run();
// or WindowSpec::font_smoothing(..), or Tx::set_font_smoothing(..) while running
```

The gallery does this. Linux and the web already default to `Off`.

## The generator

Values are not written by hand. `crates/spectrum-rune/src/{tokens,icons,constraints}/generated.rs`
come from:

```sh
cargo xtask gen
```

The oracle (CLI version range and dataset commit) is pinned in one file, [`oracle.toml`](oracle.toml).
The generator needs a `design-data` CLI inside that range on `PATH` (`brew install design-data`; outside the
`cli_min`/`cli_max` in `oracle.toml` is rejected). It needs no checkout: the CLI reads the foundation release
pinned in `.design-data.toml` (a github source, fetched and cached), and `dataset` is the commit of the release
pinned in `platforms/rune/manifest.json`. It runs `design-data catalog export` for the components, icons and
recipes, so it needs a CLI that writes `visuals/` (0.32.0, adobe/spectrum-design-data#1750); the `regen-*.sh`
scripts read the same release.
The generated files' headers record the real CLI version and dataset commit. To move to
a newer oracle: edit `oracle.toml`, run `cargo xtask gen` and every `regen-*.sh`, and fix what the
diffs show, all in one change.

It writes three files: `tokens` (per colour scheme
and scale, plus recipe-scoped values the export omits), `icons` (Spectrum UI icons as Rune `Icon`s)
and `constraints` (the catalogs' option rules). Output is deterministic: running it again on the same
dataset changes nothing.

## How verification works

- **Oracle fixtures.** For each component, `design-data render <component> --format scene` renders
  Spectrum's own recipe to a scene (rectangles, radii, colours, strokes, text boxes). The results are
  checked in under `crates/spectrum-rune/tests/fixtures/*_scene.json`, regenerated by the
  `regen-*.sh` scripts next to them (run one from the repo root, e.g.
  `bash crates/spectrum-rune/tests/fixtures/regen-switch.sh`; they need the same CLI as the generator and
  read the foundation release pinned in `.design-data.toml`, fetched and cached by the CLI. Each script
  checks the CLI version against `oracle.toml` and warns if the manifest and `.design-data.toml` pins differ;
  pass a spectrum-design-data checkout as `$1` to read that instead). Each component's test builds the same case in a headless Rune runtime and compares
  geometry and colours (1 px, 3 per channel).
- **Wrapping.** `tests/wrap.rs` checks the five wrapping components at a request width against
  `*_wrap.json`: container width, height (for Rune's own line count, which depends on the installed
  font: with Adobe Clean it equals the oracle's, Rune's fallback sans is wider and breaks earlier),
  pill radius, control and label position. A case the oracle wraps must wrap here too.
  CI cannot check the exact line count (no Adobe Clean), so after bumping `oracle.toml` or changing
  wrapping code, run it locally with the font installed:
  `cargo test -p spectrum-rune --test wrap -- --include-ignored`.
- **Constraints.** The cross product of options is large and partly undefined. The regen scripts
  skip combinations a catalog marks `error` (`fixtures/constraints.sh`), and the builders refuse
  them in debug builds.
- **Pixel helper.** `tests/support/pixels.rs` paints a headless runtime's instances with `rune-ref`
  (Rune's CPU reference renderer, no GPU) to assert things `ElementInfo` cannot give. It shows what
  Rune's instance stream says it draws, not the Metal/wgpu output (text is drawn differently, and
  tests run at scale 1), and colours are read at chosen pixels rather than from a property.
  Switch, Checkbox, Radio-button and Button (`tests/{switch,checkbox,radio_button,button}_pixels.rs`)
  assert **border colour and width and focus-ring colour, thickness and gap** this way, and the
  keyboard-focus look of all of them, Action-button (`tests/pixels.rs`) and Accordion
  (`accordion_pixels.rs`): the focus fill inside its radius, clipped, the label / icon ink, the
  unchanged stroke where Rune cannot change it (`*_focus.json`, `button_focus_fill.json`), against
  values read from the oracle fixtures (`*_scene.json`, `*_rings.json`, `button_focus_ring.json`),
  never from our `Tokens`: a wrong token choice cannot pass. Translucent colours are blended over the
  page in linear light, as Rune does. Border drawing in Rune is inside the box and snapped to whole
  pixels; all the oracle's widths for these four are the integral 2px, so they are compared exactly,
  and a pressed (scaled) button is compared at its snapped edge. Action-button, Badge and Accordion
  use the same helper.
- **Mutation checked.** The component tests were checked by breaking a component on purpose and
  confirming a test fails.

## Known gaps

- **Keyboard-focus look.** Keyboard focus takes the oracle's hover look besides the ring, with
  Rune's `El::focus_fill` (an opaque fill laid over the part's own fill, never from pointer focus) and
  `hover_group_focus` + `group_color` (text and icon colour): Button's fill (a14.29), Switch (handle
  fill unselected, track fill selected, label), Checkbox (selected / indeterminate box fill, label),
  Radio-button (selected control fill, label), Action-button (selected container fill, also quiet
  and static selected + emphasized) and Accordion (title and chevron); Badge has none (not
  focusable). Matched values (light; dark is the mirrored token): neutral `41` to `19` (dark `219`
  to `242`), emphasized accent `59,99,251` to `39,77,234`, Checkbox error `215,50,32` to
  `183,40,24`. Analysis in `tests/fixtures/focus-diff.sh`; beads a14.32 to a14.36.
  **Not possible with Rune's API:** the **stroke** colour in focus of the UNSELECTED Switch track,
  Checkbox box and Radio control (2px, `41` to `19` light, `219` to `242` dark; error Checkbox
  `215,50,32` to `183,40,24`), which stays at its rest colour (Rune has no focus-visible border colour;
  anomalyco/rune#106, bead a14.14); and the view cannot see focus, so Button's hover +
  keyboard-focus (focus wins over hover for an outline's stroke and label and a secondary fill's
  label, `41`/`218` instead of hover's `19`/`198`) is not drawn, and neither is the oracle's hover +
  keyboard-focus for an unselected Action-button (focus wins: icon and label `41` where we draw hover's
  `19`, and a non-quiet fill `233` where we draw hover's `225`; quiet's hover wash `225` matches) (beads
  a14.14, a14.31).
- **Font family.** Tests cannot observe which family Rune resolved; only the ignored font tests and the gallery's
  measurement can. (Border and ring colour and geometry of Switch, Checkbox, Radio-button and
  Button are now asserted from pixels; the family is not.)
- **Pixel limits.** The pixel tests render Rune's instance stream with its CPU reference renderer,
  at scale 1 and in 8-bit sRGB: they prove what Rune emits, not what the GPU path shows (the
  gallery notes heavier light-on-dark text in `rune-ref`). Not asserted from pixels: Button's pending
  progress ink (the oracle's `gray_800` is a colour we deliberately do not copy), selected
  Switch borders (the oracle's stroke equals the fill, so the width cannot be seen), the ring's
  rounded corners, and the oracle's focus-visible stroke colour (bead a14.14).
- **High contrast.** The tokens exported for high contrast are identical to regular upstream, and
  Windows forced colours are not designed.
- **RTL** is not handled.
- **Accordion group.** The recipe has no group part (`items` and `isMultiple` are not visual), so the
  group's layout (gap 0, each item keeping its divider) has no oracle: only the stacked item heights are
  checked against the item oracle. Per-item `disabled` is a Rune-side convenience; the catalog's
  `items[]` has no `isDisabled`. Items are `AccordionItem`s, so each can carry the direct actions below.
- **Action-button static + disabled** draws the plain disabled pill (opaque grey on the coloured
  backdrop), because that is what the oracle renders; Button's recipe has translucent rules for it
  and Action-button's does not (bead a14.23, proposed upstream in #1693).
- **Accordion direct actions.** `AccordionItem::action_button(|b| ..)` and `::switch(|s| ..)` build the
  recipe's trailing icon-only action button (hold icon always on) and label-less switch from our
  `ActionButton` and `Switch`, and the item fixes their size, hidden label, hold icon and disabled state
  (`tests/accordion_actions.rs`: geometry and colours of 69 oracle cases, each action alone and both).
  The row is a sibling of the header button, not inside it, so the header's focus ring stops before the
  actions (the oracle's `header` spans them). Hover is tracked on the wrapping row, so the item's wash
  and title and chevron ink hold while the pointer is over the actions, which keep their own looks;
  press and keyboard focus stay on the header (the oracle changes nothing else in those states). Hold
  is checked headlessly, not with a real pointer. The oracle draws the switch unselected and the button
  at rest, so there is no oracle for their selected, hover, keyboard-focus or pending states (the
  controls' own tests cover those), and the switch track's stroke is not asserted here
  (`ElementInfo` has no border; `switch_pixels.rs` does).
  From M up the oracle's item is at its minimum width, so the title-to-actions gap is only asserted
  at S, laid out at its natural width. Bead a14.28.
- **Accordion content inset.** `AccordionItem::content` is flush with the item's left edge (the
  oracle's `content` has only vertical padding); pad it yourself to sit under the title (bead
  a14.24, proposed upstream in #1693).
- **Recipe findings** (outline badges for 19 variants render as bold, and others) are collected
  upstream in [adobe/spectrum-design-data#1693](https://github.com/adobe/spectrum-design-data/issues/1693).

## Development

CI (`.github/workflows/ci.yml`) runs `cargo fmt --all --check`,
`cargo clippy --workspace --all-targets -- -D warnings` and `cargo test --workspace`, on Ubuntu
(`libxkbcommon-dev` is installed because winit, via Rune, links it). That `check` job is the
required one and stays fast. A separate `gallery` job (not required) renders every gallery scene
with Rune's CPU reference renderer, sized to its content, and uploads them as the `gallery`
artifact. Tasks are tracked with [beads](https://github.com/gastownhall/beads) (`bd`);
`bd ready` lists the available work and `bd show <id>` the details.

The repository is private; nothing here links to anything that is not in it or public.

## Releasing

[release-plz](https://release-plz.dev) (`release-plz.toml`, `.github/workflows/release-plz.yml`) keeps a release PR
open on main with the version bump (`crates/spectrum-rune/Cargo.toml`, `Cargo.lock`) and `CHANGELOG.md`.

1. Open the release PR and click "Approve and run workflows": CI runs on a PR the bot opened only after a
   manual approval (no PAT is configured, as in ferrograph). Merge once CI is green. release-plz then tags the merge commit `vX.Y.Z` and creates the GitHub
   release (versions come from `v*` tags; nothing goes to crates.io because `rune` is a git dependency).
2. Edit the release notes: what ships, the oracle (CLI and foundation versions) and the known gaps.
3. In spectrum-design-data, set `tag = "vX.Y.Z"` under `[platforms.rune]` in `.design-data.toml`, check
   `design-data validate-manifest --platform rune` from a clean `[cache] dir`, and open a PR.

A pin must name a commit whose `platforms/rune/manifest.json` is the one consumers should validate. Without
conventional commits (`feat:`, `fix:`) release-plz proposes a patch bump; override the version in the release PR.
