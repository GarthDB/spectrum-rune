# spectrum-rune

Adobe Spectrum components for [Rune](https://github.com/anomalyco/rune), a Rust UI toolkit.
Every colour, size, radius and type value comes from the Spectrum design data, generated by the
`design-data` CLI into plain Rust (`cargo xtask gen`); the components only arrange those values.

Status: pre-release, not published. Rune itself is pre-release, so the `rune` dependency is pinned
by git rev (see [Installing](#installing)) and may change.

Built so far (all verified against Spectrum's own renderer, see [Verification](#how-verification-works)):

| Component | Module | State the app owns |
|---|---|---|
| Switch | `switch` | `selected` |
| Checkbox (incl. indeterminate, error) | `checkbox` | `selected` |
| Radio button (one button, not a group) | `radio_button` | `selected` |
| Button | `button` | none (`pending` and `disabled` are inputs) |
| Action button | `action_button` | `selected` for a toggle |
| Badge | `badge` | none (static) |
| Accordion item (one item, not a group) | `accordion` | `open` |

## Installing

The crate is not on crates.io. Depend on it by path or git, and pin Rune to the same rev this
repo uses (the workspace `Cargo.toml` is the source of truth):

```toml
[dependencies]
spectrum-rune = { path = "../spectrum-rune/crates/spectrum-rune" }
rune = { git = "https://github.com/anomalyco/rune", rev = "07c369b13e8bd82c3f0a74164bd132965de88830" }
rune-kit = { git = "https://github.com/anomalyco/rune", rev = "07c369b13e8bd82c3f0a74164bd132965de88830" }
```

`rune-kit` is needed because Button and Action button borrow its progress indicator.
The toolchain is pinned in `rust-toolchain.toml`.

## Using it

Tokens are chosen per colour scheme and scale; hand the `&'static Tokens` to every `build`:

```rust,no_run
use rune::{col, AppSpec, Cx, El};
use spectrum_rune::switch::Switch;
use spectrum_rune::tokens::{tokens, ColorScheme, Scale};

struct App {
    wifi: bool,
}

fn view(app: &App, cx: &mut Cx<App>) -> El {
    let scheme = if cx.system_dark() { ColorScheme::Dark } else { ColorScheme::Light };
    let t = tokens(scheme, Scale::Desktop); // Scale::Mobile for the touch sizes
    col().padding(16.0).child(
        Switch::new("wifi")
            .label("Wi-Fi")
            .selected(app.wifi)
            .on_toggle(|app: &mut App| app.wifi = !app.wifi)
            .build(t),
    )
}

fn main() {
    rune::run(AppSpec::new("demo", (320.0, 120.0), || App { wifi: false }, view));
}
```

**State.** A component is a builder that returns an `El` for one frame. It never stores
`selected` or `open`: you pass the current value in and flip your own state in the handler
(`on_toggle`, `on_select`, `on_press`), as above. Rune rebuilds the view after the handler runs.

**Keys and `Interaction`.** Hover and press colours are whole-colour swaps, so a component rebuilds
with the pointer state it reads from `interaction::Interaction::of(key)`. The `key` you pass to
`Component::new(key)` is that lookup, so it must be unique per instance across the whole view
(two buttons with the same key share a hover). It also prefixes the parts, `{key}/container`,
`{key}/label` and so on, which is what `rt.find(..)` and scripts address. Keyboard focus needs no
state: Rune draws the focus ring only for the keyboard.

**Sizes.** Switch, Checkbox, Radio button, Button, Badge and Accordion item take `Size` (`S`, `M`,
`L`, `XL`). Action button's recipe also has `XS`, so it takes `ActionButtonSize`; a plain `Size`
converts, so `.size(Size::M)` works there too, while `XS` on a Switch does not compile.

**Option constraints.** Spectrum's catalogs say which option combinations are undefined (an accent
button has no outline, for instance). Builders `debug_assert!` that, so a bad combination panics in
debug builds and renders what the reference renders in release. Call `constraints::check(name,
&component.options())` to test a combination yourself; the gallery does, and skips the invalid ones.

One minimal use of each (all compiled by `cargo test`, as doctests of this file):

```rust,no_run
use rune::El;
use spectrum_rune::accordion::{AccordionItem, Density};
use spectrum_rune::action_button::ActionButton;
use spectrum_rune::badge::{self, Badge};
use spectrum_rune::button::{self, Button};
use spectrum_rune::checkbox::Checkbox;
use spectrum_rune::icons::ADD_100;
use spectrum_rune::radio_button::RadioButton;
use spectrum_rune::tokens::Tokens;
use spectrum_rune::Size;

struct App {
    agree: bool,
    pick: u8,
    bold: bool,
    open: bool,
}

fn parts(app: &App, t: &'static Tokens) -> Vec<El> {
    vec![
        Checkbox::new("agree")
            .label("I agree")
            .selected(app.agree)
            .on_toggle(|a: &mut App| a.agree = !a.agree)
            .build(t),
        RadioButton::new("pick-1")
            .label("One")
            .selected(app.pick == 1)
            .on_select(|a: &mut App| a.pick = 1)
            .build(t),
        Button::new("save")
            .label("Save")
            .variant(button::Variant::Primary)
            .style(button::Style::Outline)
            .icon(&ADD_100)
            .size(Size::L)
            .on_press(|_: &mut App| println!("saved"))
            .build(t),
        ActionButton::new("bold")
            .label("Bold")
            .quiet(true)
            .selected(app.bold)
            .on_press(|a: &mut App| a.bold = !a.bold)
            .build(t),
        Badge::new("status")
            .label("Approved")
            .variant(badge::Variant::Positive)
            .style(badge::Style::Subtle)
            .build(t),
        AccordionItem::new("details")
            .title("Details")
            .density(Density::Regular)
            .open(app.open)
            .on_toggle(|a: &mut App| a.open = !a.open)
            .content(rune::text("Content below the header."))
            .build(t),
    ]
}
```

## Gallery

`crates/spectrum-rune/examples/gallery` shows every component with its interesting options. The
toggles really toggle (click or Space/Enter), and the header switches the colour scheme and the
scale live. Its page colour is Spectrum's `background_base_color` (white in light, near-black in dark; the oracle's scenes have no backdrop, so this is the named page token).

```sh
cargo run -p spectrum-rune --example gallery
cargo run -p spectrum-rune --example gallery -- --list-scenes
```

Headless screenshots (need a GPU; Rune renders offscreen). A scene is a component, optionally
suffixed `-dark` (forces the dark scheme) or `-mobile` (the mobile scale). Without `--theme`, a
snapshot follows the machine's current appearance:

```sh
cargo run -p spectrum-rune --example gallery -- --scene button --theme dark --size 1100x1000 --snap /tmp/button-dark.png
cargo run -p spectrum-rune --example gallery -- --scene button-mobile --theme light --snap /tmp/button-mobile.png
```

Scenes: `switch`, `checkbox`, `radio-button`, `button`, `action-button`, `badge`, `accordion`.

CI also renders every scene with Rune's CPU reference renderer (no GPU) and uploads the PNGs as the
`gallery` artifact; locally: `cargo test --release -p spectrum-rune --example gallery -- --ignored`
writes them to `target/gallery/`.

## Fonts

Spectrum's typeface, Adobe Clean Spectrum VF, is licensed. **It is never committed or embedded
here.** Rune loads installed fonts by family name, and the components ask for this list
(`font::FAMILY_LIST`):

```text
Adobe Clean Spectrum VF, Adobe Clean Spectrum, Source Sans 3
```

Without the licensed font you get the next name that is installed, ending at Rune's default sans.
Source Sans 3 is only a width-compatible stand-in (it is what the `design-data` CLI measures text
with); nothing will look like Spectrum, and text widths can differ slightly. To see the real thing,
install the font files you are licensed for into the system (macOS: open them in Font Book; Linux:
copy to `~/.local/share/fonts` and run `fc-cache -f`). The gallery measures a sample string against
Rune's default sans to tell whether the family resolved, and says so in its header and on startup
(`Adobe Clean Spectrum VF found` or `... NOT found: showing the fallback`). The same check runs as
the ignored tests in `src/font.rs`: `cargo test -p spectrum-rune -- --ignored`.

## The generator

Values are not written by hand. `crates/spectrum-rune/src/{tokens,icons,constraints}/generated.rs`
come from:

```sh
cargo xtask gen
```

It needs the `design-data` CLI at 0.20.x on `PATH` and a checkout of
[spectrum-design-data](https://github.com/adobe/spectrum-design-data) at `~/repos/spectrum-design-data`
(or `SPECTRUM_DESIGN_DATA=/path`) that is clean and at `origin/main` (it runs `git fetch` there);
`--allow-dirty` skips the clean/at-main check. It writes three files: `tokens` (per colour scheme
and scale, plus recipe-scoped values the export omits), `icons` (Spectrum UI icons as Rune `Icon`s)
and `constraints` (the catalogs' option rules). Output is deterministic: running it again on the same
dataset changes nothing.

## How verification works

- **Oracle fixtures.** For each component, `design-data render <component> --format scene` renders
  Spectrum's own recipe to a scene (rectangles, radii, colours, strokes, text boxes). The results are
  checked in under `crates/spectrum-rune/tests/fixtures/*_scene.json`, regenerated by the
  `regen-*.sh` scripts next to them (run one from the repo root, e.g.
  `bash crates/spectrum-rune/tests/fixtures/regen-switch.sh`; they need the same CLI and dataset
  as the generator). Each component's test builds the same case in a headless Rune runtime and compares
  geometry and colours (1 px, 3 per channel).
- **Constraints.** The cross product of options is large and partly undefined. The regen scripts
  skip combinations a catalog marks `error` (`fixtures/constraints.sh`), and the builders refuse
  them in debug builds.
- **Pixel helper.** `tests/support/pixels.rs` paints a headless runtime's instances with `rune-ref`
  (Rune's CPU reference renderer, no GPU) to assert things `ElementInfo` cannot give, such as the
  chevron's rotation or a divider's colour. It shows what Rune's instance stream says it draws, not
  the Metal/wgpu output (text is drawn differently, and tests run at scale 1), and colours are
  read at chosen pixels rather than from a property.
- **Mutation checked.** The component tests were checked by breaking a component on purpose and
  confirming a test fails.

## Known gaps

- **Keyboard-focus colours.** Rune draws a focus ring in one colour; Spectrum's per-variant
  keyboard-focus colours need a Rune change (bead a14.14).
- **Font family.** Tests cannot observe which family Rune resolved; only the ignored font tests and the gallery's
  measurement can.
- **High contrast.** The tokens exported for high contrast are identical to regular upstream, and
  Windows forced colours are not designed.
- **RTL** is not handled.
- **Groups.** Accordion (several items, `isMultiple`, arrow keys) and radio groups are not built;
  a single `AccordionItem` and `RadioButton` are (beads a14.15, a14.20).
- **Recipe findings** (outline badges for 19 variants render as bold, and others) are collected
  upstream in [adobe/spectrum-design-data#1693](https://github.com/adobe/spectrum-design-data/issues/1693).

## Development

CI (`.github/workflows/ci.yml`) runs `cargo fmt --all --check`,
`cargo clippy --workspace --all-targets -- -D warnings` and `cargo test --workspace`, on Ubuntu
(`libxkbcommon-dev` is installed because winit, via Rune, links it). That `check` job is the
required one and stays fast. A separate `gallery` job (not required) renders every gallery scene
with Rune's CPU reference renderer, sized to its content, and uploads them as the `gallery`
artifact. Tasks are tracked with [beads](https://github.com/gastownhall/beads) (`bd`);
`bd ready` lists the available work and `bd show <id>` the details.

The repository is private; nothing here links to anything that is not in it or public.
